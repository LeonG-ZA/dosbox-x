# MC88110 interpreter and the hybrid PIX emulation (Milestone 2, hybrid option)

Decision (user, after Gate 1): **hybrid**. CPU A (geometry, command interpreter) runs the real firmware in an MC88110 interpreter.
CPU B (rasteriser) is replaced by HLE, with the interpreter as a fallback for anything not yet implemented.

## Code

| File | Role |
|---|---|
| `src/hardware/su2000/m88110.{h,cpp}` | interpreter: integer, load/store (GRF and XRF), bit-field, branches with delay slots, traps, control registers, data BATC, FP, graphics unit |
| `src/hardware/su2000/m88110_ops.inc` | decode table generated from MAME's mc88110 disassembler table (BSD-3-Clause, AJR) by `tools/gen_m88110_inc.py` |
| `src/hardware/su2000/pixboard.{h,cpp}` | one processor card: DRAM, VRAM + SAM row transfers, FIFO ring, status register, CPU scheduling, B draw-list dispatch hook, frame conversion |
| `src/hardware/su2000/pixraster.cpp` | HLE handlers for draw-list records |
| `src/hardware/su2000/pix1000.cpp` | DOSBox-X ISA side: ports, window, a worker thread per card |
| `su2000/tests/run_pix.cpp` | standalone harness: replays a captured host session (`tools/make_replay.py`) into one card and writes frames |

No firmware is embedded. Everything runs from what the game uploads.

## Instruction semantics: certainty

| Area | Status |
|---|---|
| Integer, logical, bit-field, load/store, branches, delay slots | from the 88100/88110 manuals as recalled, and consistent with all firmware tested (SP/DN2/ETS/SFL boot and DN2 runs) |
| `cmp` result bits | bits 2..11 as on the 88100 (eq, ne, gt, le, lt, ge, hi, ls, lo, hs) [confirmed by use]; bits 0/1 not implemented |
| `fcmp` | bits 2..11 including range bits [inferred] |
| FP | computed in double, rounded to float for single-precision destinations; extended (`.x`) = double [approximation] |
| `flt` with bit 9 set | destination in the extended register file (encoding missing from MAME's table) [inferred, same bit as `mov`] |
| `tb0`/`tb1`/`tcnd` | trap via VBR + 8×vector. `tb1 0,r0,0` is used as a pipeline sync [confirmed by use] |
| `padd`/`psub` (+ saturating) | 64-bit register pair, 8/16/32-bit fields [confirmed by the edge stepping in draw32B] |
| `punpk.b`/`pmul`/`padd.h`/`ppack.32.h` | byte → low half of 16-bit field; field × 32-bit multiplier truncated to 16 bits; pack the high byte of each field. Gives exact `(s·a + d·(256−a)) >> 8` blending as used by the bitmap code [consistent] |
| `ppack` | result is the 64-bit pair (rS1 pair << R) \| packed fields; the firmware always uses rD+1 and chains two `ppack.32` to fill a pair [confirmed by every use site; fixing this removed the false "static" on the DN2 title] |
| `punpk.n`, `prot` | unpack nibbles / 64-bit rotate [inferred; output looks right] |
| `pcmp` | approximated as `cmp` on the low words [unverified, unused in the paths seen] |
| Interrupts | none modelled; the vectors only lead to a register-dump handler. The firmware polls |
| Caches/CMMU | ignored, except the data BATC (needed for the 0x1000_0000 alias) |

Performance: about 55 M instructions/s combined (single host core) after pre-decoding FP ops and adding direct memory pointers.

## Board behaviour learnt by running the firmware

* Boot: each CPU starts at 0 in the memory state at its own RUN, so B (uploaded first) starts `mainB` and A starts `mainA`.
* VRAM clears and backdrops use VRAM row transfers (see `PROTOCOL.md` §9). Without them old frames show through.
* The video line counter must take every value (`waitVBI` tests for equality). It is clocked from CPU A's instruction count
  (3200 instructions per 64 µs line, 312 lines), not from host time.
* DN2 uses 16-bit pixels (768×250 visible per channel at 1536-byte stride in its attract mode).

## Results

* Harness (DN2 replay, B interpreted): set-up menu, spinning chrome VR logo, title, high-score table, 3D attract scenes.
* DOSBox-X (`[su2000] enable=true`, emulation on): DN2 boots both channels, reaches its main loop and renders the 3D attract demo
  on both channels in real time-ish (the game reports `F = 18.18`). Frames: `pix window = true` (SDL2) or `pix frame dump = dir`.

## Open points

* HLE coverage is partial; see `drawlist.md`. Unimplemented records run in the interpreter, so output is still correct.
